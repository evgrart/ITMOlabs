# Лабораторная работа: `fnv32_1_hash` для VLIW-IV

## Назначение программы

Программа вычисляет 32-битный хэш строки по алгоритму FNV-1. Она написана на ассемблере архитектуры `VLIW-IV` и предназначена для запуска в эмуляторе Wrench 0.0.5.0.

Строка поступает через memory-mapped I/O в формате C-string: каждый символ передаётся отдельным 32-битным словом, а конец строки обозначается нулевым словом. Полученный хэш записывается одним 32-битным словом в выходной порт.

Главное архитектурное требование для VLIW-IV — использование внутреннего параллелизма процессора. Поэтому независимые операции программы объединены в широкие пакеты и выполняются одновременно разными исполнительными устройствами.

Файлы работы:

- [`fnv32_1_hash.s`](./fnv32_1_hash.s) — программа на ассемблере;
- [`fnv32_1_hash.yaml`](./fnv32_1_hash.yaml) — конфигурация и основной тест Wrench.

## Формат входа и выхода

Для ввода и вывода используются два отображённых в память порта:

| Адрес | Назначение |
|---:|---|
| `0x80` | входной поток символов |
| `0x84` | выходной поток с хэшем |

В YAML символы задаются их числовыми кодами. Например, строка `abc\0` представляется так:

```yaml
0x80: [97, 98, 99, 0]
```

Здесь:

- `97` — код символа `a`;
- `98` — код символа `b`;
- `99` — код символа `c`;
- `0` — признак конца строки.

После вычисления хэш записывается в порт `0x84`:

```yaml
0x84: [1134309195]
```

Это десятичная запись значения `0x439C2F4B`.

Каждое выполнение `lw` по адресу `0x80` извлекает следующее слово входного потока. Нулевой терминатор также считывается, но не участвует в вычислении хэша.

## Алгоритм FNV-1

FNV-1 использует две 32-битные константы:

| Константа | Значение |
|---|---:|
| начальное значение хэша, offset basis | `0x811C9DC5` |
| множитель FNV prime | `0x01000193` |

Для каждого ненулевого символа выполняются две операции:

```text
hash = (hash * 0x01000193) mod 2^32
hash = hash XOR character
```

Псевдокод алгоритма:

```text
prime = 0x01000193
hash = 0x811C9DC5
character = read_word(0x80)

while character != 0:
    product = hash * prime
    hash = product XOR character
    character = read_word(0x80)

write_word(0x84, hash)
```

Переполнение при умножении является частью алгоритма. Сохраняются только младшие 32 бита произведения, что эквивалентно операции по модулю `2^32`. Поэтому такое переполнение не считается ошибкой и не должно приводить к выводу `0xCCCCCCCC`.

## Отличие FNV-1 от FNV-1a

В FNV-1 сначала выполняется умножение, а затем XOR:

```text
hash = hash * prime
hash = hash XOR character
```

В FNV-1a порядок обратный:

```text
hash = hash XOR character
hash = hash * prime
```

В данной программе реализован именно первый вариант. Перестановка этих операций изменит результат и приведёт к провалу тестов.

## Архитектура VLIW-IV

VLIW расшифровывается как Very Long Instruction Word. Одна машинная команда VLIW-IV представляет собой пакет длиной 112 бит, или 14 байт. Пакет содержит четыре слота:

```text
[ ALU1 | ALU2 | MEM | CTRL ]
```

| Слот | Размер | Назначение |
|---|---:|---|
| `ALU1` | 32 бита | арифметические и логические операции |
| `ALU2` | 32 бита | арифметические и логические операции |
| `MEM` | 24 бита | загрузка и сохранение данных |
| `CTRL` | 24 бита | переходы, вызовы и остановка |

В ассемблерном коде операции разных слотов разделяются символом `/`:

```asm
операция_ALU1 / операция_ALU2 / операция_MEM / операция_CTRL
```

Например:

```asm
xor s1, t1, t0 / nop / lw t0, 128(zero) / j hash_loop
```

В одном такте этот пакет:

1. вычисляет новое значение хэша в ALU1;
2. не использует ALU2;
3. читает следующий символ через блок памяти;
4. выполняет переход к началу цикла через блок управления.

## Модель параллельного выполнения

Все исходные операнды пакета читаются до записи результатов. Затем результаты операций записываются одновременно. Управляющая операция применяется последней.

Это означает, что команда чтения нового символа и команда XOR могут безопасно находиться в одном пакете:

```asm
xor s1, t1, t0 / nop / lw t0, 128(zero) / j hash_loop
```

Операция XOR получает старое значение `t0`, то есть текущий символ. Операция `lw` записывает в `t0` новый символ только в конце выполнения пакета. Поэтому XOR не увидит загруженное значение преждевременно.

При ручном планировании пакетов необходимо избегать конфликтов:

- RAW, read after write: операция пытается использовать результат другой операции того же пакета;
- WAW, write after write: несколько слотов записывают разные результаты в один регистр;
- нежелательных зависимостей между памятью, ALU и переходом.

В программе все операции одного пакета либо независимы, либо намеренно используют старые значения регистров в соответствии с моделью VLIW-IV.

## Используемые регистры

| Регистр | Назначение |
|---|---|
| `zero` | постоянный ноль и базовый адрес для прямого обращения к портам |
| `s1` | текущее значение хэша |
| `s2` | константа FNV prime `0x01000193` |
| `t0` | код текущего символа |
| `t1` | промежуточное произведение `hash * prime` |

Регистры `sp` и `ra` не используются. Для VLIW-варианта лабораторной работы обязательным требованием является внутренний параллелизм, а не использование вложенных процедур и стека. Вся вычислительная часть представляет собой компактный статически распланированный цикл.

## Размещение программы в памяти

Секция машинного кода начинается с адреса `0x100`:

```asm
.text
.org 0x100
```

Программа состоит из пяти разных VLIW-пакетов. Размер каждого пакета равен 14 байтам, поэтому общий размер кода составляет:

```text
5 * 14 = 70 байт
```

Отдельная секция данных не требуется: обе константы формируются в регистрах, а адреса портов помещаются непосредственно в смещения операций памяти.

## Разбор программы по пакетам

### Первый пакет: старшие части констант и первый символ

```asm
lui s2, %hi(0x01000193) / lui s1, %hi(0x811c9dc5) / lw t0, 128(zero) / nop
```

Одновременно выполняются три независимые операции:

- ALU1 загружает старшую часть FNV prime в `s2`;
- ALU2 загружает старшую часть offset basis в `s1`;
- MEM читает первый символ из порта `0x80` в `t0`;
- CTRL не используется.

Адрес операции `lw` вычисляется так:

```text
zero + 128 = 0 + 0x80 = 0x80
```

Поскольку операции записывают результаты в разные регистры, конфликтов нет. Пакет использует три из четырёх исполнительных слотов.

### Второй пакет: младшие части констант

```asm
addi s2, s2, %lo(0x01000193) / addi s1, s1, %lo(0x811c9dc5) / nop / nop
```

Два ALU одновременно завершают формирование констант:

```text
s2 = 0x01000193
s1 = 0x811C9DC5
```

Здесь также отсутствует конфликт: каждая операция читает и записывает собственный регистр.

### Первый пакет цикла: умножение и проверка символа

```asm
mul t1, s1, s2 / nop / nop / beqz t0, hash_end
```

ALU1 вычисляет:

```text
t1 = s1 * s2
```

Одновременно CTRL проверяет текущий символ. Если `t0 == 0`, выполняется переход к `hash_end`.

Умножение и проверка независимы:

- `mul` читает `s1` и `s2`, затем записывает `t1`;
- `beqz` читает `t0`;
- общих регистров назначения у них нет.

Если текущий символ равен нулю, умножение всё равно выполняется, но записывает только временный регистр `t1`. Основной хэш находится в `s1` и не изменяется, поэтому нулевой терминатор не включается в результат.

### Второй пакет цикла: XOR, чтение и переход

```asm
xor s1, t1, t0 / nop / lw t0, 128(zero) / j hash_loop
```

Пакет одновременно выполняет три действия:

```text
s1 = t1 XOR старое_t0
t0 = read_word(0x80)
pc = hash_loop
```

ALU1 вычисляет окончательное значение хэша для текущего символа. MEM читает следующий символ. CTRL возвращает выполнение к началу цикла.

Хотя XOR и `lw` используют регистр `t0`, конфликта нет. XOR читает значение `t0` в начале пакета, а `lw` записывает новый символ в конце пакета.

### Последний пакет: вывод и остановка

```asm
nop / nop / sw s1, 132(zero) / halt
```

MEM записывает итоговый хэш по адресу:

```text
zero + 132 = 0 + 0x84 = 0x84
```

Одновременно CTRL выполняет `halt`. Управляющий слот применяется после остальных слотов, поэтому запись результата завершается до остановки машины.

## Граф потока управления

```text
_start
  |
  | инициализация prime, hash и первого символа
  v
hash_loop
  |
  | hash * prime и проверка t0
  |
  +---- t0 == 0 ----> hash_end ----> запись результата и halt
  |
  +---- t0 != 0 ----> XOR, чтение следующего символа
                         |
                         +----------> hash_loop
```

## Пример вычисления для строки `a`

Начальные значения:

```text
hash = 0x811C9DC5
prime = 0x01000193
character = 0x61
```

Сначала выполняется умножение с сохранением младших 32 бит:

```text
0x811C9DC5 * 0x01000193 mod 2^32 = 0x050C5D1F
```

Затем выполняется XOR с кодом символа `a`:

```text
0x050C5D1F XOR 0x00000061 = 0x050C5D7E
```

Следующий символ равен нулю, поэтому результат записывается в выходной порт:

```text
0x050C5D7E = 84696446
```

## Пример вычисления для строки `abc`

Изменение хэша после каждого символа:

| Символ | Код | Произведение | Хэш после XOR |
|---|---:|---:|---:|
| `a` | `0x61` | `0x050C5D1F` | `0x050C5D7E` |
| `b` | `0x62` | `0x70772D5A` | `0x70772D38` |
| `c` | `0x63` | `0x439C2F28` | `0x439C2F4B` |

Итог:

```text
fnv32_1_hash("abc") = 0x439C2F4B = 1134309195
```

## Количество выполняемых пакетов

Для строки из `N` ненулевых символов выполняется:

- два пакета инициализации;
- по два пакета для каждого символа;
- один пакет проверки нулевого терминатора;
- один пакет вывода и остановки.

Итоговая формула:

```text
bundles = 2N + 4
```

Для `abc`, где `N = 3`:

```text
bundles = 2 * 3 + 4 = 10
```

Основной тест показывает следующие характеристики:

```text
Total bundles executed: 10
Total code size:        70
Slot utilization:       60%
Average active slots:   2.40
```

Таким образом, программа в среднем использует 2,4 исполнительного слота из четырёх на каждый выполненный пакет.

## Синтаксис ассемблера VLIW-IV

### Секция `.text`

Директива `.text` начинает секцию исполняемого кода:

```asm
.text
```

### Директива `.org`

Директива `.org` задаёт начальный адрес последующего кода:

```asm
.org 0x100
```

Числа с префиксом `0x` записываются в шестнадцатеричной системе.

### Метки

Метка является символическим именем адреса и заканчивается двоеточием:

```asm
hash_loop:
```

Метки используются в условных и безусловных переходах. Ассемблер преобразует имя в относительное смещение до нужного пакета.

Метка `_start` обязательна и определяет точку входа программы.

### Разделитель `/`

Символ `/` отделяет слоты одного VLIW-пакета:

```asm
ALU1 / ALU2 / MEM / CTRL
```

В каждой строке программы должны быть представлены четыре слота. Неиспользуемый слот заполняется командой `nop`.

### `nop`

Команда `nop` означает отсутствие операции в соответствующем слоте:

```asm
mul t1, s1, s2 / nop / nop / beqz t0, hash_end
```

В этом пакете активны ALU1 и CTRL, а ALU2 и MEM простаивают.

`nop` в разных слотах кодируется по-разному, поскольку каждый слот имеет собственный набор операций.

### `lui`

Инструкция `lui` доступна в слотах ALU1 и ALU2 и загружает старшую часть константы:

```asm
lui s2, %hi(0x01000193)
```

Она используется вместе с `addi` и `%lo(...)` для формирования полного 32-битного значения.

### `%hi(...)` и `%lo(...)`

Конструкции `%hi` и `%lo` разбивают 32-битную константу на старшую и младшую части:

```asm
lui s1, %hi(0x811c9dc5)
addi s1, s1, %lo(0x811c9dc5)
```

После выполнения двух пакетов в `s1` находится полное значение `0x811C9DC5`.

Вторую инструкцию нельзя поместить в один пакет с первой, поскольку все операции пакета читают старые значения регистров. `addi` не увидела бы результат `lui` того же пакета.

### `addi`

Инструкция прибавляет непосредственную константу к значению регистра:

```asm
addi s2, s2, %lo(0x01000193)
```

Общий вид:

```text
addi rd, rs, immediate
```

Операция:

```text
rd = rs + immediate
```

### `mul`

Инструкция умножает значения двух регистров:

```asm
mul t1, s1, s2
```

Общий вид:

```text
mul rd, rs1, rs2
```

В `rd` сохраняются младшие 32 бита произведения. Это соответствует требуемой арифметике FNV-1 по модулю `2^32`.

### `xor`

Инструкция выполняет побитовое исключающее ИЛИ:

```asm
xor s1, t1, t0
```

Для каждого разряда результат равен единице, если соответствующие биты операндов различаются.

Операция:

```text
s1 = t1 XOR t0
```

### `lw`

Инструкция `lw` находится только в слоте MEM и читает 32-битное слово:

```asm
lw t0, 128(zero)
```

Общий формат:

```text
lw rd, offset(base)
```

Эффективный адрес вычисляется как:

```text
address = base + offset
```

В программе `zero` всегда равен нулю, поэтому `128(zero)` соответствует адресу `0x80`.

### `sw`

Инструкция `sw` находится в слоте MEM и записывает 32-битное слово:

```asm
sw s1, 132(zero)
```

Общий формат:

```text
sw rs, offset(base)
```

Адрес `132(zero)` равен `0x84`, поэтому значение `s1` отправляется в выходной поток.

### `beqz`

Инструкция `beqz` располагается в слоте CTRL и выполняет переход, если регистр равен нулю:

```asm
beqz t0, hash_end
```

Эквивалентное условие:

```text
if t0 == 0:
    pc = hash_end
```

### `j`

Инструкция `j` выполняет безусловный переход:

```asm
j hash_loop
```

Она находится в слоте CTRL и не сохраняет адрес возврата.

### `halt`

Инструкция `halt` останавливает симуляцию:

```asm
halt
```

Управляющий слот выполняется после остальных операций пакета, поэтому `sw` и `halt` можно безопасно объединить.

### Комментарии

Синтаксис VLIW-IV использует символ `;` для начала комментария:

```asm
mul t1, s1, s2 / nop / nop / nop ; вычисление произведения
```

В итоговом исходном файле комментарии не используются, чтобы код оставался компактным. Их назначение приведено в данном описании.

## Синтаксис YAML-конфигурации

### Название теста

```yaml
name: "assert fnv32_1_hash('abc\0') == 1134309195"
```

Поле описывает проверяемое выражение. Последовательность `\0` обозначает нулевой терминатор строки.

### Ограничение выполнения

```yaml
limit: 2000
```

Wrench остановит программу с ошибкой, если количество выполненных пакетов превысит это значение.

### Размер памяти

```yaml
memory_size: 0x1000
```

Для модели выделяется `4096` байт памяти.

### Memory-mapped I/O

```yaml
memory_mapped_io:
  0x80: [97, 98, 99, 0]
  0x84: []
```

Порт `0x80` содержит входные коды символов, а порт `0x84` перед запуском пуст.

### Пошаговый отчёт

Отчёт `Step-by-step` создаётся для каждого состояния машины:

```yaml
slice: all
```

В нём отображаются:

- `S1` — текущий хэш;
- `T0` — текущий символ;
- `T1` — промежуточное произведение;
- `pc` — адрес текущего пакета;
- `instruction:next` — содержимое VLIW-пакета;
- `pc:label` — метка текущего адреса.

### Статистика VLIW

Используются специальные поля:

```yaml
{vliw:load-percent}
{vliw:avg-load}
{vliw:bundles-by-load}
```

Они показывают:

- процент занятых слотов;
- среднее количество активных слотов на пакет;
- распределение пакетов по количеству используемых слотов.

Эти показатели подтверждают, что программа действительно использует внутренний параллелизм.

### Проверка результата

Итоговый отчёт содержит утверждения:

```yaml
numio[0x80]: [] >>> []
numio[0x84]: [] >>> [1134309195]
```

Первое утверждение требует, чтобы вся строка вместе с терминатором была прочитана. Второе утверждение проверяет, что в выходном потоке появился правильный хэш.

## Представление беззнаковых результатов

FNV-1 возвращает 32-битный набор битов. Если старший бит равен единице, Wrench может показать то же значение как отрицательное знаковое число.

Например:

```text
0xE97BD97F = 3917207935 unsigned
0xE97BD97F = -377759361 signed
```

Обе записи описывают одинаковое 32-битное машинное слово. В отчёте удобно дополнительно смотреть регистр и результат в шестнадцатеричном формате.

## Проверенные примеры

| Входная строка | Результат в hex | Результат в YAML `dec` |
|---|---:|---:|
| `a\0` | `0x050C5D7E` | `84696446` |
| `abc\0` | `0x439C2F4B` | `1134309195` |
| `Computers are awesome!\0` | `0xE97BD97F` | `-377759361` |
| `\0` | `0x811C9DC5` | `-2128831035` |

Первые три примера входят в официальный набор тестов варианта. Пустая строка дополнительно проверяет правильность обработки терминатора: для неё возвращается неизменённый offset basis.

## Ограничение входного потока

Корректная C-string обязательно должна содержать нулевой терминатор. Если он отсутствует, программа продолжит чтение, пока входной поток Wrench не закончится. После этого симулятор завершится ошибкой `input is depleted`.

ISA не предоставляет инструкции, позволяющей заранее проверить количество оставшихся элементов или перехватить ошибку опустевшего потока. Поэтому наличие терминатора является частью контракта входных данных.

## Итог

Программа корректно реализует FNV-1 для 32-битного машинного слова и обрабатывает строку до нулевого терминатора. Арифметика естественным образом выполняется по модулю `2^32`.

Требование VLIW выполнено за счёт статического объединения независимых операций:

- две константы формируются параллельно;
- первый символ читается одновременно с загрузкой старших частей констант;
- умножение выполняется одновременно с проверкой терминатора;
- XOR выполняется одновременно с чтением следующего символа и переходом;
- вывод результата выполняется одновременно с остановкой машины.

В основном тесте занято в среднем `2.40` слота на пакет, а общая загрузка четырёх исполнительных слотов составляет `60%`.
